# Roster Guides scope

- Canonical/effective book projections own gameplay facts consumed by roster/runtime code.
- `effective-points-catalog.mjs` and the effective-points projection consume canonical pre-render facts.
- `points-data.js` is generated by `build-points.mjs`; it is not a factual source.
- Roster text input, equipment selection, attachments, current wounds, and battle state are runtime state, not source facts.
- Shared roster behavior lives primarily under `books/shared/`; expand there only when the reproduction reaches a shared mechanism.
- Do not read book reader, target, roster, mobile, or glossary generated outputs as points facts.
- Run `npm run qa:roster` for roster parser/projection/runtime changes.
- Run `npm run qa:points` for point identity/value/projection changes.
- Add affected `qa:<book>` commands for faction-specific effects, selectors, attachments, or loadouts.
- Add `npm run qa:integration` for route, storage, or publication wiring changes.
- Browser suites are appropriate only when the real rendered roster consumer is part of the defect.
- Do not change canonical data to accommodate a parser or compatibility-copy bug.
